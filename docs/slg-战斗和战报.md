已对比 新系统设计文档 与现有源码（ GameState.js 、 battle.js 、 GameConstants.js 、 UIScene.js ），主要风险如下：

## 一、高风险：新系统与现有战斗模型不匹配
1. 合击/军团战斗没有落地方案
   
   - 当前 _arriveAndFight 把多名出征武将聚合成一个军团（加权攻防、最慢速度），与守将队伍逐场连战。
   - 新文档是“按速度排序、每个武将单独行动”的回合制，完全没说明多名玩家武将如何与多名守将队伍交战。
   - 风险：直接替换 resolveBattle 会让现有合击、多队连战逻辑全部失效。
2. 连击 / 谎报 破坏“数据驱动、无需改战斗逻辑”的目标
   
   - 文档第 17 条声称“后续新增战法无需修改战斗逻辑”，但：
     - 连击 是“普攻后追加一次普攻”的触发时机特例；
     - 谎报 是控制状态特例，没有伤害。
   - 风险：每新增一种触发时机或效果，就要改战斗流程。建议直接采纳文档末尾的 Skill 抽象方案 （普通攻击/战法统一为“技能 + 触发时机”）。
3. 随机浮动与可复现性冲突
   
   - 文档伤害公式加入 95%~105% 随机浮动，但现有 battle.js 明确是“确定性，同输入必同结果”。
   - 风险：战报回放、离线重连、未来 PVP 校验都会出现结果不一致。如保留随机，必须使用战斗种子 + 确定性 RNG。
## 二、中风险：状态与战斗流程细节缺失
4. 谎报 持续回合语义不清
   
   - 文档写“持续 1 回合、回合结束自动解除”，但没说明：
     - 是本回合施加后立刻在回合末解除（等于无效）？
     - 还是持续到目标下一次行动后解除？
   - 风险：实现错误会让控制战法变成 0 收益。
5. 目标选择边界未定义
   
   - 随机敌军 在目标已死亡时如何重选、 targetCount 大于存活敌人时是否自动降频，文档未说明。
   - 风险：会出现选中尸体、伤害丢失或数组越界。
6. 未限定最大回合数
   
   - 文档没有战斗回合上限。如果双方高防低攻，可能陷入死循环。
   - 建议继承现有 BATTLE_MAX_ROUNDS 机制。
7. 死亡/行动顺序的边界
   
   - 流程只写“检查是否死亡 → 检查控制状态”，没说明速度相同如何决定先后手、已阵亡武将是立即移除还是保留到回合末。
## 三、中风险：数据/存档/经济
8. int 智力属性在存档中丢失
   
   - GameState.js:687-690 保存武将时只存了 spd/atk/def ， 没有存 int 。
   - 新系统用智力计算谋略战法伤害，加载后智力会回退到模板基础值，导致等级/觉醒/铁匠坊的智力加成丢失。
9. 玉石 经济与武将销毁未对接现有代码
   
   - 文档新增“武将销毁获得 1 玉石、玉石兑换战法”。
   - 当前 dismissGeneral 只是遣散，没有玉石；资源对象也没有 jade 字段。
   - 风险：不补全来源和存储，战法兑换系统无法闭环。
10. 存档版本需要迁移
    
    - 当前存档 v:5 ，新系统需要保存：战法仓库、战法绑定关系、武将智力、玉石。
    - 如果不做版本迁移和旧档兼容，加载旧档会直接缺失战法数据或属性错误。
## 四、低风险但需注意
11. 战报 BattleEvent 与现有日志体系是两套东西
    
    - 现有 _pushLog 只存 50 条文本 + 简单 report 对象。
    - 新系统要求 BattleEvent[] 作为战斗动画/回放/统计/AI 的唯一数据源。
    - 需要重写战斗结算为“先跑事件流，再派生战报/统计/日志”，而不是先打再补事件。
12. 伤害公式数值需验证
    
    - 损失兵力 = 守军当前兵力 × Clamp(0.05, 0.3×攻/防, 0.80) ，上限 80% 意味着快节奏下 1~2 回合即可决胜负。
    - 如果按现有属性（武将攻击/防御 ~100、兵力 1000+）带入，攻防值比值接近 1，每击约 30% 当前兵力，波动会很大，建议先做数值模拟。
13. 守将没有战法
    
    - 文档只给玩家武将设计战法，守将（guards）没有任何战法配置。
    - 短期降低难度，但会让高级地/NPC 城过于简单；长期需要给守将也配置技能。
## 建议
1. 先统一抽象层 ：把普通攻击和所有战法都抽象为 Skill （触发时机 + 倍率 + 概率），再实现战斗流程，否则“数据驱动”会流于口号。
2. 保留确定性 ：要么去掉随机浮动，要么使用战斗种子生成确定性随机序列，保证回放和离线结算一致。
3. 明确合击规则 ：在按武将行动的回合制里，补全“多名玩家武将 vs 多队守军”的交战规则（如整场战斗还是分场连战、兵力是否按将独立）。
4. 补齐存档/经济 ：保存 int 、战法仓库、绑定关系、玉石；升级存档版本；给 dismissGeneral 增加玉石产出。
5. 补充边界定义 ：状态持续/解除时机、目标死亡重选、速度相同平局、最大回合数、连击目标已死时的处理。

# 三、统一伤害计算公式

所有普通攻击、主动战法均采用同一套公式。

---

## Step1：计算攻击值

```
攻击值 = 当前兵力 × (1 + 对应属性 / 300)
```

不同攻击类型使用不同属性：

| 类型 | 使用属性 |
|------|---------|
| 普通攻击 | 武力 |
| 武力战法 | 武力 |
| 智力战法 | 智力 |
| 速度战法 | 速度 |

例如：

```
兵力：1000
武力：90

攻击值

=1000×(1+90/300)

=1300
```

---

## Step2：计算攻击倍率

普通攻击固定倍率：

```
1.0
```

战法拥有自己的倍率：

| 战法 | 倍率 |
|------|------|
| 挥砍 | 1.0 |
| 践踏 | 0.75 |
| 火攻 | 1.5 |
| 落雷 | 1.0 |
| 连击 | 普通攻击追加一次 |
| 谎报 | 无伤害 |

---

## Step3：计算最终攻击值

```
最终攻击值

=

攻击值
×
攻击倍率
×
随机浮动(95%~105%)
```

随机浮动用于避免每次伤害完全一致。

---

## Step4：计算防御值

```
防御值

=

当前兵力
×
(1 + 防御 / 300)
```

例如：

```
兵力1000

防御90

=

1300
```

---

## Step5：计算伤害率

```
伤害率

=

Clamp(

0.05,

0.30 × 最终攻击值 / 防御值,

0.80

)
```

说明：

- 最低造成5%兵力损失
- 最高造成80%兵力损失
- 避免一回合直接秒杀

---

## Step6：最终损失兵力

```
损失兵力

=

守军当前兵力

×

伤害率
```

例如：

```
守军兵力

1000

伤害率

30%

最终损失

300
```

# 十一、控制状态事件

例如：

```
郭嘉

获得【谎报】

持续1回合
```

事件：

```json
{
    "type":"status_add",
    "status":"谎报",
    "duration":1
}
```

下一回合：

```
郭嘉

受到【谎报】

无法行动
```

事件：

```json
{
    "type":"status_skip",
    "status":"谎报"
}
```

结束：

```
谎报解除
```

事件：

```json
{
    "type":"status_remove",
    "status":"谎报"
}
```

# 十二、数据统计

战斗结束后，根据 BattleEvent 自动统计。

每位武将建议统计：

| 字段 | 说明 |
|------|------|
| 总输出 | Damage Done |
| 总承伤 | Damage Taken |
| 战法发动次数 | Skill Trigger |
| 战法成功次数 | Skill Success |
| 普攻次数 | Normal Attack |
| 连击次数 | Extra Attack |
| 控制次数 | Control Count |
| 存活回合 | Survival Round |
| 剩余兵力 | Remain Soldier |

玩家可以快速知道：

- 谁输出最高
- 谁最能抗
- 谁控制最多
- 谁战法脸黑

# 十四、BattleEvent 的优势

BattleEvent 是整个战斗系统的唯一数据来源。

```
Battle

↓

BattleEvent[]

├── 战斗动画
├── 战斗回放
├── 战斗录像
├── 玩家战报
├── AI复盘
├── 数据统计
└── 开发调试
```

任何新玩法（治疗、暴击、反击、持续伤害、BUFF、天气、兵种克制等），只需新增对应 Event 类型，而无需修改战报结构。
