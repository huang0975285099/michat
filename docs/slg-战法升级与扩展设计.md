# 战法升级与扩展设计（V1.2）

> 本文档基于 `frontend/src/games/slg/game/core/skills.js` 的 Skill 抽象与 `slg-战斗和战报.md` 的战斗流程设计，仅做方案输出，暂不进入开发。

---

## 一、设计目标

1. **战法总数 20 个**：保留并调整现有 6 个，新增 14 个。
2. **全部战法可升级**，最高 **Lv.10**。
3. **数据驱动**：所有战法仍只通过 `skills.js` 配置，不改动战斗逻辑即可生效（新增的战法均复用现有 `damage` / `control` / `extra_attack` 效果）。
4. **等级成长有明确规则**：发动概率、伤害倍率、控制持续回合随等级线性提升，升级消耗有统一曲线。
5. **各战法期望收益（EV）在同一数量级**，避免某个战法一家独大。

---

## 二、战法数据字段（含升级扩展）

在现有字段基础上，新增等级相关字段：

| 字段 | 说明 |
|------|------|
| `id` | 唯一 ID（仓库/绑定/存档 key） |
| `name` | 显示名 |
| `timing` | 触发时机：`beforeAction`（行动前主动战法） / `onAttack`（普通攻击本体） / `afterAttack`（普攻后追击） |
| `rate` | Lv.1 发动概率（%） |
| `rateStep` | 每升 1 级发动概率增加量（%），通常 +2% |
| `attribute` | 伤害属性：`atk`（武力） / `int`（智力） / `spd`（速度）；控制/追击可不填 |
| `mult` | Lv.1 伤害倍率 |
| `multStep` | 每升 1 级倍率增加量，按档位：单体伤害 0.05 / 群体伤害 0.03 / 追击 0.025 |
| `target` | 目标类型：`random_enemy`（随机敌军） |
| `targetCount` | 目标数量（超过存活敌军数时只打存活者） |
| `effect` | `damage` / `control` / `extra_attack` |
| `status` | control 效果施加的状态 ID |
| `duration` | Lv.1 控制持续回合 |
| `durationScaleLevels` | 控制战法在哪些等级延长 1 回合，如 `[5, 10]` |
| `useCounter` | 伤害是否叠加兵种克制（仅普通攻击 true；战法 false） |
| `cost` | 玉石兑换消耗（第三期经济用） |
| `maxLevel` | 固定 10 |
| `desc` | 玩家可见描述 |

**等级生效公式（建议）**：

```text
发动概率(lv) = rate + (lv - 1) × rateStep
伤害倍率(lv) = mult + (lv - 1) × multStep
控制持续(lv) = duration + 满足 lv ≥ durationScaleLevels 的个数
```

**multStep 分档**（按战法定位，控制群体成长速度避免低倍率群体战法满级过强）：

| 档位 | 适用战法 | multStep | Lv.1→Lv.10 增量 |
|------|----------|----------|-----------------|
| 单体伤害 | targetCount=1 的 `damage` 战法 | 0.05 | +0.45 |
| 群体伤害 | targetCount≥2 的 `damage` 战法 | 0.03 | +0.27 |
| 追击类 | `extra_attack` 战法 | 0.025 | +0.225 |

> 例：`rate=40`, `rateStep=2` → Lv.10 发动率 = 40 + 9×2 = **58%**。  
> 例：挥砍 `mult=1.0`, `multStep=0.05`（单体档）→ Lv.10 倍率 = 1.0 + 9×0.05 = **1.45**。  
> 例：践踏 `mult=0.45`, `multStep=0.03`（群体档）→ Lv.10 倍率 = 0.45 + 9×0.03 = **0.72**。  
> 例：连击 `mult=1.0`, `multStep=0.025`（追击档）→ Lv.10 倍率 = 1.0 + 9×0.025 = **1.225**。  
> 例：`duration=1`, `durationScaleLevels=[5,10]` → Lv.1~4 为 1 回合，Lv.5~9 为 2 回合，Lv.10 为 3 回合。

**控制状态叠加规则**：同一目标被同名控制状态多次命中时，**取 max 覆盖**而非累加，避免连续命中导致超长控制破坏平衡：

```javascript
target.statuses[skill.status] = Math.max(target.statuses[skill.status] || 0, skill.duration || 1)
```

> ⚠️ 现有 `battle.js` 中 `doControl` 实现是累加（`+=`），开发时需改为 `Math.max` 覆盖。  
> 不同名控制状态（如谎报+迷阵）可同时并存、各自独立倒计时，不受此规则影响。

## 六、升级系统

### 6.1 等级上限

每个战法最高 **Lv.10**，获得时默认为 **Lv.1**。

### 6.2 升级消耗

使用 **玉石** 升级。从 Lv.n 升到 Lv.n+1 的消耗：

```text
升级消耗 = cost × n
```

其中 `cost` 为该战法的玉石兑换价，`n` 为当前等级。

| 战法兑换价 | Lv.1→2 | Lv.2→3 | ... | Lv.9→10 | 总消耗 |
|------------|--------|--------|-----|---------|--------|
| 20 | 20 | 40 | ... | 180 | 900 |
| 25 | 25 | 50 | ... | 225 | 1125 |
| 30 | 30 | 60 | ... | 270 | 1350 |
| 35 | 35 | 70 | ... | 315 | 1575 |

> 设计意图：低价战法升级便宜，高价战法上限更高，与兑换成本一致。

### 6.3 各字段成长

| 字段 | 每级成长 | Lv.1→Lv.10 总成长 |
|------|----------|-------------------|
| 发动概率 | +2% | +18% |
| 伤害倍率（单体） | +0.05 | +0.45 |
| 伤害倍率（群体） | +0.03 | +0.27 |
| 伤害倍率（追击） | +0.025 | +0.225 |
| 控制持续 | 在 Lv.5、Lv.10 各 +1 回合 | 最多 +2 回合 |

> 控制持续不线性增长，是为了避免满级出现 10 回合长控破坏平衡。

### 6.4 等级存储与存档迁移

在 `GameState` 中新增：

```javascript
this.skillLevels = {}   // { skillId: level }
```

- 未记录的战法默认 Lv.1。
- 解绑/销毁武将不影响战法等级（等级跟战法走，符合率土惯例）。

**存档版本 v7 → v8 迁移**（`GameState.js` 同步改动）：

```javascript
// save() 中加入字段
const data = {
  v: 8,                       // 7 → 8
  // ...
  skills: this.skills.slice(),
  skillLevels: { ...this.skillLevels },   // 新增
  // ...
}

// load() 中读取
if (data.skillLevels) gs.skillLevels = { ...data.skillLevels }
// v7 旧档无 skillLevels → 保持构造时的 {} ，所有已拥有战法自动 Lv.1
```

> 迁移兼容：v7 旧档加载后 `skillLevels={}`，6 个旧战法默认 Lv.1，玩家无感。`data.v < 8` 仍可加载，无需重置存档。
> V1.1 风险清单第 8 条「int 智力属性在存档中丢失」已在 v7 修复（`GameState.js:716` 持久化 `int`），本次升级无需再处理。

### 6.6 玉石经济闭环

战法兑换与升级都需要「玉石」资源，当前 `GameState.res` 没有 `jade` 字段、`dismissGeneral` 不产出玉石、`buySkill`/`upgradeSkill` 入口缺失，需补全来源、存储、消耗三个环节。

**1. 资源字段**（`GameState.js` 构造函数）：

```javascript
this.res = { coin: 0, wood: 0, food: 0, iron: 0, jade: 0 }   // 新增 jade
```

**2. 玉石来源**——武将销毁按品质产出：

| 品质 | basic(平庸) | common(普通) | rare(精良) | elite(精锐) | legend(王牌) |
|------|-------------|-------------|-----------|------------|-------------|
| 玉石 | 1 | 2 | 5 | 10 | 20 |

> 数值依据：与招募概率（0/50/30/15/5%）成反比，稀有武将更值钱。  
> 期望产出 ≈ 5 玉石/次招募销毁，20 玉石战法需销毁 ~4 个平均武将，30 玉石战法满级（1350）需 ~270 个，符合 SLG 长线积累节奏。

```javascript
// GameConstants.js 新增常量，便于配置调整
export const DISMISS_JADE = {
  basic: 1, common: 2, rare: 5, elite: 10, legend: 20,
}

// GameState.js
dismissGeneral(id) {
  // ... 现有遣散逻辑
  const jadeGain = DISMISS_JADE[g.quality] ?? 1
  this.res.jade += jadeGain
  this._pushLog(`🗑️ 遣散 ${g.name}（${GENERAL_QUALITY[g.quality].name}），获得 ${jadeGain} 玉石`)
  this.emit('res', this.res)
  return { success: true, jade: jadeGain }
}
```

**3. 玉石消耗**——兑换与升级 API：

```javascript
// 兑换战法（首次获取，消耗 sk.cost）
buySkill(skillId) {
  const sk = getSkill(skillId)
  if (!sk) return '战法不存在'
  if (this.skills.includes(skillId)) return '已拥有该战法'
  if (this.res.jade < sk.cost) return `玉石不足（需 ${sk.cost}）`
  this.res.jade -= sk.cost
  this.skills.push(skillId)
  this.emit('skills', this.skills)
  this.emit('res', this.res)
  return null
}

// 升级战法（消耗 = cost × 当前等级）
upgradeSkill(skillId) {
  const sk = getSkill(skillId)
  if (!sk || !this.skills.includes(skillId)) return '未拥有该战法'
  const lv = this.skillLevels[skillId] || 1
  if (lv >= sk.maxLevel) return '已满级'
  const cost = sk.cost * lv
  if (this.res.jade < cost) return `玉石不足（需 ${cost}）`
  this.res.jade -= cost
  this.skillLevels[skillId] = lv + 1
  this.emit('skills', this.skills)
  this.emit('res', this.res)
  return null
}

// 读取战法当前等级（BattleUnit 构造时调用）
skillLevel(skillId) { return this.skillLevels[skillId] || 1 }
```

**4. 存档**：`res.jade` 已包含在 `res` 对象中随存档持久化，无需额外字段。旧档加载时 `res` 合并逻辑（`{ ...gs.res, ...data.res }`）会自动补 `jade:0`。

> 经济闭环：销毁武将 → 产出玉石 → 兑换/升级战法 → 战力提升 → 推更高等级地 → 获得更多武将 → 销毁冗余武将。形成正向循环。

## 九、设计原则总结

1. **不引入新效果类型**：20 个战法全部复用 `damage` / `control` / `extra_attack`，确保不做大改即可落地。
2. **升级只改数值**：不改变目标数、不改变触发时机、不改变效果类型。
3. **概率与倍率同步成长**：发动率和倍率都成长，避免高等级只有单一维度提升导致体验单调。
4. **控制持续保守成长**：只在关键等级点提升，防止控制链过长。
5. **消耗与兑换价挂钩**：越贵的战法升级越贵，保持经济系统一致。
