# 门派 PK · 梦幻西游风（暂定名：menpai）设计文档

> 基于梦幻西游 7 门派（大唐官府 / 化生寺 / 龙宫 / 方寸山 / 普陀山 / 魔王寨 / 狮驼岭）
> 的 1v1 回合制 PK 游戏。**首期做单机 PVE（人 vs AI）**，后续扩展阵容与联机。
>
> 用 Phaser.js 渲染战斗场景，Vue Page 负责挂载与路由，参照本项目 `slg` / `ironfist` 的结构约定。
>
> 与现有 `menpai-pk.md`（9 个原创门派的草案）是**不同的独立设计**，本文档为 v0.1。

---

## 一、玩法定位

- **核心循环**：选种族（人/魔/仙，过滤可选门派）→ 选门派 → 1v1 回合制 PK → 胜负结算 → 再来一局。
  - 种族仅用于过滤门派范围（人族→大唐/化生/方寸，仙族→龙宫/普陀，魔族→魔王/狮驼），
    展示对应的初始五维属性（体质/魔力/力量/耐力/敏捷，见 `docs/梦幻西游-人物属性参考.md`）作为选择参考，
    暂不参与战斗数值计算（门派固定 base 属性不变）。
- **单位关系**：玩家 1 名角色 vs AI 1 名角色，共 2 个单位同场。
- **节奏**：单局 5~15 回合，3~8 分钟一局，碎片化可玩。
- **策略重心**：门派克制、技能时机、愤怒管理（必杀技）、状态博弈（封印/中毒/灼烧）。

## 三、属性系统（简化版）

参考梦幻西游但做大幅简化：门派 base 数值手调保证 1v1 平衡，**种族只影响成长率**，
不做五维（体质/魔力/力量/耐力/敏捷）逐点加点。五维仅在选种族界面展示，供玩家理解种族画像。

### 面板属性

| 属性 | 含义 | 备注 |
|---|---|---|
| HP | 气血 | 归零判负 |
| MP | 魔法 | 技能消耗，每回合自然回 5% 上限 |
| ATK | 物理攻击 | 物理技能基数 |
| MATK | 法术攻击 | 法术技能基数 |
| DEF | 物理防御 | 减物理伤害 |
| MDEF | 法术防御 | 减法术伤害 |
| SPD | 速度 | 决定回合内出手先后 |
| 愤怒 | 特技资源 | 上限 150，受伤害/出手获取，满 150 放必杀 |
| 暴击率 | 默认 5% | 暴击伤害 ×1.5 |

### 伤害公式

```
基础伤害 = 攻击力 × 技能倍率 − 防御力 × 0.5
保底伤害 = 攻击力 × 技能倍率 × 0.1
最终伤害 = max(基础伤害, 保底伤害) × (暴击 ? 1.5 : 1) × 随机波动(0.9~1.1)
```

固定伤害（普陀五行）无视防御，直接 `技能基础值 × 等级系数`。

## 三之二、等级与经验系统（`game/leveling.js` + `game/save.js`）

### 经验公式

对 17173《梦幻西游每级升级经验列表》（端游）做三次多项式拟合，得到精确闭式解：

```
expToNext(L) = ceil(4.8·L³ + 14.4·L² + 50.4·L + 40)      // L 级升到 L+1 所需经验
```

原表 20/21/25/26/27/29/30/31/40/45/50 等 16 个数据点**全部命中**（原表即本式向上取整）。
等级上限 109（与门派技能参考文档一致），满级后不再累计经验。

### 等级成长：种族决定成长率

面板属性按**占门派 base 的百分比**线性成长，而非参考文档里的绝对成长值（如魔族 1 体质 = 6 血）：

```
stat(L) = round(base × (1 + rate × (L - 1)))
```

> **为什么不用绝对成长值**：门派 base 是为 1v1 手调的（大唐 ATK 130 / 龙宫 MATK 130）。
> 若用绝对值，攻击成长（约 1.3/级）会被气血成长（约 10/级）远远甩开，高等级会退化成互相磨血。
> 按比例成长可保证 TTK 跨等级恒定 —— 实测大唐普攻打死龙宫在 Lv.1 / Lv.30 / Lv.109 均为 **9 击**。

| 种族 | hp | mp | atk | matk | def | mdef | spd | 画像（对应参考文档） |
|---|---|---|---|---|---|---|---|---|
| 人族 | .040 | .040 | .040 | .040 | .040 | .040 | .040 | 全属性均衡，无专长无短板 |
| 魔族 | .048 | .034 | .046 | .046 | .032 | .032 | .034 | 体质力量成长高，耐力敏捷低 |
| 仙族 | .034 | .048 | .032 | .044 | .048 | .046 | .040 | 魔力耐力成长高，体质力量低 |

三族 rate 总和接近，只改变属性侧写，不失衡。

### 经验结算

```
expReward = expToNext(玩家等级) × 胜负系数 × 等级差修正
胜负系数：胜 0.34 / 平 0.12 / 负 0.06        → 约 3 场胜利升 1 级
等级差修正：clamp(1 + (敌方等级 − 玩家等级) × 0.15, 0.4, 2.0)
敌方等级：跟随玩家等级 ±1（rollEnemyLevel），保证战斗强度不脱节
```

### 存档

`localStorage` key `menpai:character:v1`，存 `{raceId, factionId, level, exp, wins, losses, draws}`。
读取时校验种族/门派/等级合法性，损坏或旧版本数据一律视为无存档。隐私模式下读写异常被吞掉，不影响本局。

- 种族+门派与存档一致 → 沿用等级经验；否则从 1 级新角色开始。
- 种族选择界面若检测到存档，顶部提供「继续冒险：门派 Lv.N」直接开战。

## 五、战斗系统

### 回合流程

1. **回合开始结算**：DoT（中毒/灼烧）扣血、持续状态回合数 -1、到期解除、MP 自然回 5%。
2. **双方选择行动**：玩家通过 UI 选技能；AI 按策略选技能。
   - 可选行动：使用主动技能 / 防御（本回合受伤 -50%，不主动出手）/ 使用必杀（满 150 愤怒时）。
3. **行动队列**：双方按 SPD 高低排序，同速则本局随机种子决定（全局一次）。
4. **依次结算**：检查眩晕/封印/睡眠，被控则跳过；检查 HP，归零则判负。
5. **愤怒获取**：仅挨打时获取，按单次伤害占最大 HP 的百分比查阶梯表（见下）。出手不获取。
6. **胜负判定**：一方 HP 归零判负；满 30 回合按剩余 HP% 判胜，相等则平局。

### 异常状态

| 状态 | 效果 | 解除 |
|---|---|---|
| 眩晕 | 跳过行动 | 1 回合后自动解除 |
| 睡眠 | 无法行动，受伤害立即苏醒 | 受伤或 2 回合后 |
| 封法 | 无法用法术技能 | 2 回合后 |
| 封物理 | 无法用物理技能 | 2 回合后 |
| 中毒 | 每回合扣 5% 最大 HP | 3 回合后 |
| 灼烧 | 每回合扣 5% 最大 HP | 3 回合后 |
| 防御 | 本回合受伤 -50% | 本回合结束 |

### 愤怒系统（严格照搬端游）

**战斗中不使用道具时，愤怒的唯一来源是挨打。攻击方出手不获得愤怒。**
愤怒是挨打的补偿、劣势方的翻盘资源 —— 这是端游的设计意图。

按**单次伤害占自身最大气血的百分比**分档（`GameConstants.ANGER_ON_DAMAGE`）：

| 单次伤害 / 最大气血 | 获得愤怒 |
|---|---|
| 0–3% | 1 |
| 3–10% | 3 |
| 10–20% | 10 |
| 20–30% | 15 |
| 30–50% | 25 |
| 50–80% | 40 |
| 80–100% | 55 |

- **阶梯而非线性**：10% 这道坎上从 3 跳到 10，奖励被打出大伤害的一方。
- **临界值取右侧**：伤害恰好等于 3%/10%/20%/30%/50%/80% 时算进更高一档（表按 min 降序，取第一个 `ratio >= min`）。
- **多段攻击每刀单独结算**：横扫千军三刀各自查表，不把伤害合并。
- 低于 3% 的伤害端游界面不显示愤怒变化，但实际每次仍 +1。
- 上限 150，满 150 可放必杀，释放后清零。死亡清零（1v1 死亡即结束）。

> **手游的表完全不同**（1/10/20/30/40/50/60 七档），数值差一倍，**勿混用**。

#### 已知后果：必杀技是稀有事件

端游这张表是为 **5v5** 设计的 —— 每回合可能挨 3~5 刀。本作 1v1 每回合只挨约
**0.44 刀**（实测 294 场 Lv.20 全门派组合），同表下攒怒速度慢约 7 倍：
一整场打满平均只攒 61 点愤怒（中位 50），够不到 150。

实测结果：**只有 9% 的对局能放出必杀**，且 7 门派中有 5 个（大唐/龙宫/方寸/魔王/狮驼）
从未触发过 —— 它们要么秒杀对手、要么被秒，活不到攒够怒。只有化生寺（57%）和普陀山（7%）
这类高耐久门派能吃到，因为它们扛得久、挨得多。

这是**有意接受的**取舍：优先忠于端游数值，而非让必杀成为常规循环技。
若日后要让必杀可用，两条等价的路（`150 ÷ 3 = 50`）：

- 保留 150 阈值 + 受伤获怒 ×3 补偿系数（模拟 5v5 被围殴），必杀仍是"150 怒"，UI 不用改；
- 或阶梯表原样、把 `MAX_ANGER` 降到 50。

两者实测均为 53% 对局能放必杀、平均 0.83 次/场、首次中位第 6 回合。

## 五之二、战斗动画与事件回放（`game/BattleFeed.js`）

### 为什么需要回放队列

`BattleEngine.resolveRound()` 是**同步**跑完整回合的：一次 `selectAction` 会在同一帧里把
`skill_cast / damage×N / status / round_end / select_start` 全部 emit 完。
场景若直接订阅 engine，所有动画会叠在同一帧，血条也会瞬间跳到回合末的值。

**BattleFeed** 夹在 engine 与场景之间：缓冲事件，按每种事件的"表演时长预算"逐条重放。
`BattleScene`（演出）与 `UIScene`（数据条/按钮）都只订阅 feed，从而严格同步。

另外 `BattleEngine.emit` 给**每个事件挂上当时的双方状态快照**（`payload.snapshot`），
`UIScene` 渲染快照而非 engine 当前状态，血条才能跟着动画一步步走。

### 事件 → 动画对照

| 事件 | 时长预算 | 演出 |
|---|---|---|
| `skill_cast`（物理） | 320ms | 突进到目标身前停住 |
| `skill_cast`（法术/固伤） | 470ms | 吟唱上浮 + 法阵光环，300ms 后放出弹道（飞行 170ms 恰好在末尾命中） |
| `skill_cast`（封印） | 340ms | 紫色吟唱 + 紫色弹道 |
| `skill_cast`（治疗/增益） | 340ms | 绿/蓝光环扩散 |
| `skill_cast`（必杀） | 780ms | 全屏白闪 + 强震 + 金色蓄力放大 |
| `skill_cast`（变身） | — | 金色脉冲 + 放大定格（`transform_off` 时收回） |
| `damage`（末击） | 520ms | 抖屏 + 闪烁 + 背离攻击者方向击退 + 伤害飘字（暴击加大加金） |
| `damage`（连击中间刀） | 300ms | 同上，节奏加快；物理补 jab，法术补快速弹道 |
| `damage`（DoT） | 520ms | 无施法者，仅轻微抖动 + 暗红飘字 |
| `heal` | 440ms | 绿色光环 + 回血飘字 |
| `defend` | 300ms | 蓝色护盾光环 + 下蹲 |
| `skill_end`（物理） | 240ms | 收势归位（多段攻击期间一直贴身） |
| `skill_end`（其它） | 0ms | 原地施法，无需归位时间 |
| `round_start` / `round_end` / `select_start` / `log` / `anger_change` | 0ms | 纯数据事件，紧跟上一条一起呈现 |

`damage` 事件带 `hitIndex / hits`，渲染层据此区分"起手第一击"（表演已由 `skill_cast` 铺垫）
与"连击中的后续刀"（需补动作），回放队列也据此缩短连击间隔。
`skill_cast` 与 `skill_end` 严格配对（60 场随机对战验证）。

**实测节奏**：每回合演出中位 1990ms、P90 3050ms、最长 4820ms（双方均放必杀/连击）；
含 AI 思考 500ms 的中位单回合约 2.5s。

## 六、AI 设计（首期简单版）

首期 AI 采用**门派策略 + 通用规则**的简单决策树：

1. **HP < 30% 且有恢复技能** → 优先治疗/防御。
2. **愤怒 ≥ 150** → 放必杀技。
3. **门派策略**：
   - 大唐：HP>50% 优先横扫千军，否则后发制人或杀气诀。
   - 化生：HP<70% 就活血，<40% 推气过宫。
   - 龙宫：龙附 → 龙腾 → 龙卷雨击循环。
   - 方寸：先手失心符封法，再五雷咒输出。
   - 普陀：紧箍咒 → 五行咒法输出，HP<50% 普度众生。
   - 魔王：飞砂走石优先，三昧真火补刀。
   - 狮驼：先变身，再鹰击/连环击。
4. **MP 不足** → 普攻（各门派普攻 = ATK × 1.0 物理或 MATK × 0.8 法术）。
5. **随机扰动**：10% 概率随机选可用技能，避免太死板。

## 七、技术架构

### 目录结构（参照 slg）

```
frontend/src/games/menpai/
├── MenpaiPage.vue              # Vue 入口，挂载 Phaser 容器（100dvh + touch-action:none）
└── game/
    ├── MenpaiGame.js           # Phaser 实例工厂 createMenpaiGame(container, opts)
    ├── GameConstants.js        # 常量：属性、回合上限、愤怒上限、三族 RACES、getMetrics
    ├── factions.js             # 7 门派数据：属性、技能定义
    ├── leveling.js             # 经验公式、种族成长率、属性换算、经验结算  ★纯逻辑
    ├── save.js                 # localStorage 角色存档读写 + 校验
    ├── battleSetup.js          # prepareBattle()：统一的开战准备（两条入口共用）
    ├── layout.js               # 战斗界面横/竖屏坐标（BattleScene 与 UIScene 唯一来源）
    ├── Emitter.js              # 极简 EventEmitter（engine 与 feed 共用）  ★纯逻辑
    ├── BattleEngine.js         # 战斗逻辑核心：回合结算、伤害计算、状态机  ★纯逻辑
    ├── BattleFeed.js           # 事件回放队列：把同步事件按动画时长逐条重放
    ├── BattleAI.js             # AI 决策树  ★纯逻辑
    └── scenes/
        ├── RaceSelectScene.js  # 种族选择（人/魔/仙）+ 存档续玩入口  ← 入口场景
        ├── SelectScene.js      # 门派选择（按种族过滤）
        ├── BattleScene.js      # 战斗演出：立绘、动画、AI 调度、经验结算面板
        └── UIScene.js          # UI 层：数据条、技能按钮、日志
```

### 场景流程

```
RaceSelect ──选种族──> Select ──选门派──> Battle (+ UI)
     │                                        │
     └───────「继续冒险」直接开战──────────────┘
                                    结算面板 →「再战一局」重开 Battle
                                             →「重选角色」回 RaceSelect
```

- 种族只过滤门派范围（人族→大唐/化生/方寸，仙族→龙宫/普陀，魔族→魔王/狮驼）并决定成长率。
- 敌方门派从全部 7 门派随机（可与玩家同门派），其种族即该门派固有种族。
- `BattleScene.create()` 负责拉起 `UIScene`（UI 需在每次开新局时重新绑定 engine/feed）。
  渲染层级由 `MenpaiGame` 里 `scene.add` 的顺序决定（UI 最后加 → 永远在上层），与 launch 时机无关。

### 数据流

```
MenpaiPage.vue
  └─ createMenpaiGame(container)
       ├─ BattleEngine  ← factions.js / leveling.computeStats（逻辑核心，纯函数式，可单测）
       │      │ 同步 emit（每个事件带 snapshot）
       │      ▼
       │   BattleFeed   ← 按动画时长逐条重放
       │      │
       │      ├──> BattleScene （立绘动画、AI 调度、结算 + 存档）
       │      └──> UIScene     （数据条渲染 snapshot、技能按钮、日志）
       └─ registry: menpai-engine / menpai-feed / menpai-character / menpai-race ...
```

**BattleEngine / BattleFeed / leveling / BattleAI 均为纯逻辑层**（BattleFeed 只需要一个提供
`time.delayedCall` 的宿主），不依赖 Phaser 渲染，便于单测和后续联机复用
（联机时双方 BattleEngine 实例同步 action log，参考 ironfist 的 event sourcing 模式）。

### 响应式布局（手机竖屏）

`layout.getBattleLayout(w, h)` 是战斗界面坐标的唯一来源 —— 角色立绘必须落在数据面板之间的
空档里，两个场景各写一份常量必然漂移。以 `h > w` 判定竖屏：

| | 横屏 | 竖屏（手机） |
|---|---|---|
| 数据面板 | 分居左右上角，条宽 240，高 118 | 上下堆叠在顶部，条宽 `min(w-40, 300)`，高压到 96（行距收紧） |
| 角色站位 | 梦幻式对角（敌左上 / 我右下） | 纵向居中排列，立绘缩小到 emoji 44px |
| 指令栏 | 右侧竖排，垂直居中 | 底部 3 列网格（4 技能 + 普攻 + 必杀 + 防御 = 7 个，3×3 放得下） |
| 回合数 | 顶部居中大红数字 | 右上角小角标（不占竖直空间） |
| 战斗日志 | 左下角面板，5 条 | 底部单行滚动（省下 80px 给立绘） |

- 选择类场景（RaceSelect / Select）用 `GameConstants.getMetrics`：竖屏下种族卡改宽扁横排、
  门派卡改 2 列并按可用宽度收缩。
- 朝向切换时立绘与结算面板会**重建**（尺寸烘进了 graphics），按钮宽度变化时也会重建。
- `MenpaiPage.vue` 用 `100dvh`（`100vh` 兜底）避免移动端地址栏遮挡，并禁掉双指缩放/下拉刷新。

## 十、待讨论问题

- 角色立绘目前用 emoji 占位，后续是否需要美术资源？（动画系统已按"容器 + 位移/缩放/光环"设计，换成精灵图不需要改演出逻辑）
- 音效是否要做？（动画事件已有明确切点，接音效成本很低）
- 普攻是否需要？还是每个门派固定 4 主动技能都消耗 MP？（当前设计：普攻始终可选，不耗 MP、不受封印限制）
- 暴击/闪避是否引入随机数？当前设计保留暴击，无闪避（法术必中、物理按命中率）。
- 联机时如何处理"双方同时选行动"的并发？参考 ironfist 的 action log 模式。
- 卡牌化：技能变手牌后，愤怒/MP 双资源是否还保留？与现有回合制骨架如何衔接？
